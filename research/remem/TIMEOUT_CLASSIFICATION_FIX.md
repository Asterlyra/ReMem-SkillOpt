# 生成代码执行超时的分类修正

2026-10-26，内网中等诊断 v1 的 core_00_42 在 20 题基线执行后中止：全部模型 HTTP 成功，但一条结构明确的 exec 阶段代码执行超时被归为基础设施故障。执行器正常启动并限时终止模型生成程序，应记录该有界执行失败；真正的服务、worker、整题超时和评分器异常仍阻止继续。

修正要求 llm_ok=true、fail_reason 的 exec-error 超时前缀、case.stage=exec、case.ok=false 与执行器超时错误同时成立，记为 failure/generated_code_timeout。无执行阶段依据的超时仍属基础设施故障；显式基础设施标志、服务失败、评分器异常优先，hard=1 与执行失败矛盾时拒绝结果契约。

不修改 120 秒代码执行限制、模型调用限制或任何方法/门控/证据约束。新增离线检查验证分类边界，以及真实 trainer 在训练失败先落盘后继续第二步。旧 v1 工件保留，不追溯改写分类或重新算成绩。

为保护冻结输入，修复先在独立 codex 分支工作树开发；原调度器停止派发新格，当前 AtomSearch 子进程继续完成其原冻结版本。合入主工作目录前必须确认该子进程已终止，再创建新的 study/version 并 verify。对照的后续结果必须按版本分别登记，不能把 v1 与新修订拼成同一完整正式矩阵。
