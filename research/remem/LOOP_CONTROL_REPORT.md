AtomSearch 完成两次提案、四次 primitive/composition 结果记录、三节点树与独立最终状态保存。第二次提案使用两条自身聚合 outcome memory；该记忆未出现验证任务 ID。递归访问次数推荐与最高验证分状态分别保存，未根据测试改选。实现仍是有公开差异清单的预算受限复现，见 [方法边界](../../docs/remem/12_ATOMSEARCH.md)。

CAM 第二步检索命中第一步记忆；模型可见文本排除了验证 ID，离线审计保留来源。四题面板不满足每组五题要求，两次最终动作均为 `cam_re_evaluate`，未采用候选。审计 `action` 是基础 bootstrap 结果，`result_action` 是完整 CAM 最终动作，报告必须使用后者。自适应预算两次使用缺少编辑来源 ID 时的最小预算回退，不能声称这一小样本验证了全部证据预算机制。

## 失败尝试保留与分类

- 20261024-v1：密钥加载后后端内存未刷新，四个基线任务遭遇 12 次 HTTP 401（8 次重试）。修复后鉴权错误立即停止，不重复重试。无 token 用量，账单未知。
- 20261024-v2 AtomSearch、20261025-v3 AtomSearch：各执行 10 个任务、1 次优化器调用，因对比证据引用契约错误停止。旧版本未保留 assistant 诊断文本，不能倒推出确切错误引用。后来显式列出允许引用的 task_id，并区分 event_id、case_id 和工件哈希。
- 额外一次优化器接口诊断：复用已有训练证据，0 次任务执行、1 次优化器请求，两条编辑通过结构校验；不计作完整搜索成功。
- 20261024-v2 CAM：为修正模型可见记忆中的验证 ID 风险而主动中断，已知 24 次 HTTP 请求。中断期间缺少部分 usage，不补造总 token；保留其部分用量与全部既有工件。
- 缺少失败或成功对比的 minibatch 显式记录 no_change，不调用优化器伪造对比。结构合法仍不证明诊断语义正确。

以上所有尝试合计 148 次启动的任务执行、183 次 HTTP、8 次重试；已知输入 480,567、输出 935,886 token。总体用量不完整。此前独立模型探针另见 [预实验报告](PREFLIGHT_REPORT.md)，未重复合并。

## 时间和费用口径

v4 AtomSearch 完整 trainer 执行耗时 739.359 秒，CAM 459.563 秒，包含基线、优化和结果保存。完整逻辑调用耗时之和分别为 1,111.231、712.343 秒；并发使该和可以大于运行墙钟时间。HTTP 响应头延迟不是完整生成耗时。

v2 只有 rollout 耗时和优化器阶段耗时；旧 `total_wall_time_s` 不含初始基线。完整逐调用耗时和整个 trainer 耗时均标缺失，不与 v4 字段直接比较。

按 2026-10-25 核对的 [DeepSeek 官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)，Flash 非高峰输入未缓存/缓存命中/输出每百万 token 分别为 $0.15/$0.003/$0.60，高峰为两倍。全部尝试中已报告 token 的估值约 $0.614–$1.228；不含缺失用量，不是账户扣费对账。内网 qwen/glm 价格尚未核实，不能沿用该价格或历史“免费”断言。

正式草案统一上限为每格 400 次优化期任务、80 次优化器逻辑调用，单调用最多 16,384 输出 token、最多三次 HTTP 尝试；另列每格 120 次最终测试。21 格加三次静态基线 draws 最多 11,280 次任务。DeepSeek 完成样本每次任务 rollout 墙钟约 17.3–21.7 秒，单按任务外推约 54–68 小时，另有优化器、重试、分析开销；72 小时目标尚不能保证。相同上限不意味着实际开销相同，也不等于账户费用硬上限。
