共启动 480 次任务、514 次 HTTP、9 次附加重试、25 次优化器逻辑调用。训练观察 240 条，正常的训练错误与服务错误分开保存。旧基础报告的 infra_failures 字段只数本方法账本事件；AtomSearch/原生对照的服务错误须同时检查公共调用账本，不能据该字段为 0 声称无基础设施错误。

已知输入 1,117,163、输出 3,320,941 token；所有格均有失败请求或响应缺失用量，整体总 token 和账单未知。各 trainer 完整执行墙钟之和 14,641.079 秒，约 4.07 小时；包含调度修复间隔的队列跨度约 4.81 小时。并发调用耗时之和不等于墙钟时间。

内网相关准备尝试另列：v1 60 次任务、64 次 HTTP；内网两步校准 20 次任务、22 次 HTTP；最小连通性及异常后检查共 5 次聊天请求。上述内网范围共 605 次模型 HTTP、12 次重试，已知输入 1,318,533、输出 3,851,713 token；不含未鉴权网络测试和此前 DeepSeek 工作，不是账户账单。

## 已有证据及其局限

- core_00 三步各 20 条训练观察均在对应提案调用前持久化，三次 M0 历史组数均为 0。两次格式失败也保存尝试，未作为正常 no_change 或采用更新。
- AtomSearch 首轮提案通过严格结构校验，单条与组合各评估 20 题、分别保留归属；第二次请求前训练失败已落盘。后续服务失败使最终推荐缺失，不能用中间树冒充完成结果。
- CAM 首轮 20 题分组保护检查通过，最终动作是 cam_re_evaluate，未采用候选。第二步检索命中一条历史，验证 ID 仅在离线审计保留。第二步服务故障阻止后续验证。
- R+M 与 M-only 均未进入第二步，故本次内网中等诊断不能验证其跨步记忆效果；此前小样本证据与本轮证据分开说明。
- 当前模型标识观察仍为 qwen→Qwen3.6-35B-A3B、glm→glm-5.3-private-19428658；异常响应中缺失标识另计，不补成该版本。接口标识不等于独立权重版本证明。
- 公式单元格读回空值引出的“写计算值”规则仍需对照任务语义审查；结构校验不能证明诊断因果正确。最终新测试池质量、来源模板分组及统一测试发布仍待完成。

## 已修复的框架问题

生成代码有明确 exec 阶段的限时失败已与服务/整题/评分器故障区分，120 秒代码执行限额不变。另修正 AtomSearch 的 JSON 字段说明、缺失模型标识的只读报告、旧 CAM 预算 step 字段兼容、队列失败状态及仅接续未启动格的控制。

运行控制/报告脚本采用独立 orchestration-r2/r3 哈希记录；模型执行源码、配置与原主 freeze 保持不变。所有旧错误和重跑工件保留，未清理错误后伪装首次运行。新的审计补充只记录本地 assistant 文本或安全元数据，不把离线诊断文本送进模型上下文，不提交原始模型回复/网关封套。

## 后续服务恢复验证

全部 v2 进程终止后，已验证的隔离修复合入主分支。后续建立独立 `intranet-recovery-20261027-v1`：两角色共用 240 秒 HTTP 等待上限，其余任务、输出、重试与优化器上限保持一致；仅执行 v2 六个失败格，每格最多一个新的恢复运行，不重跑已完成的 core_00。新结果不拼入 v2 同一性能表。

新版本增加请求正文的字节数、模型/choices 是否缺失以及白名单服务错误类别；不保存原始错误消息或请求正文。一次异常后的最小 GLM 请求在 2.125 秒内返回 OK（17 输入、34 输出 token），说明当时基本连通性正常，仍不能证明长请求稳定。恢复验证针对已观察到的等待/响应问题，不依据验证分数放宽协议。遇到明确的上下文长度、额度、认证等错误会停止继续派发，防止盲目消耗。

目前不启动正式实验。只有修复后的真实链路、数据质量与最终测试发布条件满足后，才可讨论正式冻结及 48–72 小时预算。
