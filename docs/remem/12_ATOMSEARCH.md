# AtomSearch 独立复现与验收

2026-10-24 用户选择保留正式近邻对照，并按论文独立复现。此实现不是作者代码，也不宣称复现了论文数值结果。依据 [arXiv v1](https://arxiv.org/html/2610.19951v1) 第 3 节、算法 1 和附录 B；本次公开检索尚未找到可核验作者仓库。

## 实现边界

入口 `skillopt/remem/atomsearch.py`，由现有 trainer 完成模型和数据适配器初始化后分派；共用任务审计和调用限额，不调用 ReMem 的提案、失败检索、配对门控。`atomsearch_budgeted` 必须删除 `remem` 配置，禁止测试、slow/meta/skill-aware 等额外通道。

保留论文机制：失败/成功对比的单条编辑；完整 skill 状态树；自扩展与子树共同参加 UCT；渐进扩宽；最多两条后续编辑的确定性前瞻；严格胜过 primitive 才保留组合；以保留状态相对根的收益回传；递归访问次数推荐；另存最高验证分状态。组合反馈整体归属，不拆成单条因果收益。

默认参数显式冻结在配置中：30 attempts、分支 6、深度 12、UCT 0.05、PW 1.0 / 0.5、5 specs、编辑上限 4、前瞻 2。结构检查仅检查证据归属和编辑契约，不能证明诊断语义成立。

## 复现假设与预算改动

| 项目 | 本实现的明确选择 | 对结论的影响 |
|---|---|---|
| 作者 prompt 未获得 | 自写 JSON 契约与指令，源码冻结 | 无法保证与原提案分布相同 |
| atom 划分 | 非空行作为精确锚点，一条新增/重写限一行 | 比多行逻辑规则更保守 |
| 学习 minibatch | 使用共同预抽任务序列；正式每批 20，池用尽按顺序循环 | 论文 SpreadsheetBench 每批 27；不复刻其采样分布 |
| 调用预算 | 正式上限 400 次任务执行、80 次优化器逻辑调用；实际用量另报 | 显著低于论文示例，属于预算受限比较 |
| 训练缓存 | 当前 attempt 内重入可复用，跨 attempt 是新 draw；验证同状态复用整面板 | 不是论文逐 item 全局缓存；实际成本透明记录 |
| 排序与平局 | 优化器列表即排名；UCT 平局先自扩展再创建顺序；推荐平局先创建 | 作者实现细节未公开 |
| robust 推荐停止 | 先选最常访问子节点，再在其访问数不超过 1 时停止 | 最终推荐与 best-validation 分别保存，不能看测试后换选法 |
| Outcome memory | 最近最多 24 条，完整 JSON 不超过 12,000 字符；精确编辑组合键聚合，再给近期记录 | 不做未公开的语义合并；重复面板计数不是独立样本 |
| 无有效编辑 | 记录 no_change，并回传当前节点相对根的分数；当前批缺少失败或成功时不请求模型伪造对比 | 明确不更新与输出格式错误分开 |
| 格式错误、服务故障 | 记录类型并停止，禁止用空提案静默代替 | 失败运行须单独报告 |
| 预算剩余不足前瞻 | 保留已评估 primitive 后停止 | 不作部分面板评估，也不免费补足搜索 |

失败训练记录是公共审计；AtomSearch 的模型只能看到当前训练证据及自身 outcome memory。验证反馈进入记忆的只有聚合修复/退化计数，不含验证题目、答案或逐题 ID。最终测试不参与搜索。

## 验收与运行

离线覆盖证据越界、失败/成功引用颠倒、单条契约、组合归属、弱中间节点、扩宽/深度、平局、预算停止、持久恢复及验证上下文隔离。小规模真实联调和正式验证分开记录；单元测试不能证明论文复现质量或最终准确率。

开发矩阵生成支持 `scripts/remem/study.py prepare <id> --include-skillopt-controlled --include-cam-reference --include-atomsearch`。加入 `--calibration` 生成 6 个训练任务、4 个选择任务、空测试集、两次训练重现/搜索尝试的独立预实验；各方法上限 32 次任务执行、20 次优化器调用。源码变动必须新建 ID。`run` 默认不调用模型，显式 `--execute` 才执行。

正式实验仍需：真实联调、数据质量审查、完整预算校准和最终测试发布流程。该复现本身不能作为正式实验已经完成的证据。

2026-10-25 联调修正：全失败 minibatch 无成功对比时，预检查记录 `insufficient_contrastive_evidence` 并继续下一次有预算的尝试。新子节点初始访问数为 1，自扩展次数为 0；这是本复现明确采用的计数约定。

提案接口显式提供可引用的失败/成功 `task_id` 清单，区分事件 ID、工件哈希与任务 ID。结构错误保留类别及本地 assistant 文本工件以便诊断；不提交模型原文或网关响应。
