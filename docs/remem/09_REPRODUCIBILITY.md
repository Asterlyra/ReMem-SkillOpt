# 数据、运行可靠性与复现要求

## 准备与正式运行分开

环境安装、模型联通、格式探针、合成集成验证属于准备阶段，不计入正式两三天，也不能写成 benchmark 结果。准备样例不使用最终测试。默认不复制旧 conda 环境，不把存在本地路径当成依赖已安装。

## 数据清单

上游 data 目录包含 ID/path 清单不等于完整 workbook/game 数据。必须核验 payload 存在、ID 对齐、评分程序可工作、来源 revision 与哈希。旧本地数据可按原许可引用/复制到受忽略的 data 目录，避免上传原始数据。

检查 train/selection/test 不重叠；检查 workbook 与模板来源；汇总历史测试暴露。不读取历史测试成绩来选新测试。若 120 个干净测试题不可获得，记录限制并在冻结前重新确定数据方案。

## 最低冻结内容

源代码、所有 prompt、配置解析结果、技能初始文件、任务计划、评分程序、数据 manifest、requirements/实际安装版本、Python/OS、模型请求与响应标识、采样/重试/缓存政策、arm 顺序、指标定义。

prepare 不发模型请求；verify 不改 freeze；run 要校验冻结；report 只读工件。冻结后变更必须新 study_id，不偷偷修补旧矩阵。

## 失败分类

1. task_failure：有效模型执行但答案/工作簿错误，可进失败记录。
2. infra_failure：鉴权、网络、服务、缺文件、进程超时等；单独记录并按协议处理。
3. proposal_invalid：优化器不满足 JSON/schema/来源条件；保存失败原因，原训练错题仍在。
4. no_change：有效返回且明确无需修改；与空响应不同。

保留尝试次数、时间和阶段；不要原样写包含 Authorization、请求正文或任务答案的异常日志。隐藏 SDK 重试与外层重试需统一，避免实际调用量与统计脱节。

## 中断恢复

事件写入采用临时文件+原子替换或事务，event_id 幂等；缓存键带模型、skill、任务、参数和 draw；重启后不得覆盖失败历史、重复关闭问题或重新随机划分。输出路径必须在本项目独立目录，不能指向旧 CAM 队列。

## 凭据与仓库

默认新仓库私有。提交研究说明、空模板、代码与轻量 manifest；不提交 .env、真实 key、原始模型响应、原始数据、运行 cache、用户对话或旧项目输出。模型别名和接口地址是接入资料，令牌始终只留本地。

## 完成声明

分别标注：交接可用、模块实现通过离线检查、环境探活、正式格完成、结果可解释。任何前者不自动推出后者。CI 通过不代表模型效果；补丁形式合法不代表修复有效；预算执行不代表来源真实；历史配置不代表当前已探活。
