# 研究背景与问题定义

## 1. 研究对象

Skill 是冻结执行模型读取的可复用文本指导。优化器模型根据任务执行轨迹提出编辑，再通过选择集决定采用哪个版本。本项目优化外部 skill，不微调权重，不要求梯度、隐藏状态或新的在线规划器。

研究问题：在最终反馈通常只有成功/失败的情况下，如何使 skill 的局部修改有可核验依据，并持续利用那些尚未解决、没有带来分数变化的失败？

## 2. 从当前实现看到的两个问题

**修改依据不足。** SkillOpt 并非完全自由改写：上游已有 failure_type 和 append/insert_after/replace/delete 格式。但是语法格式不能保证“某个轨迹行为—某条规则—某种修复操作”的对应关系。批量总结、合并和排序还可能丢失具体任务来源。

**失败生命周期不完整。** 原 step buffer/后续 CAM memory 主要围绕更新结果组织。失败会在本轮参与反思，但没有补丁时的提前退出，与候选是否被接受、是否出现分数变化，不应决定一道训练错题是否继续存在。不能把“原始轨迹还在磁盘”当成“优化器会继续处理这个问题”。

因此分离三个决策：①有效训练失败是否落盘；②哪些问题/修复值得分配当前预算；③新 skill 是否满足采用条件。第①项不能依赖第③项。

## 3. 最终两模块

| 模块 | 内部机制 | 输入与输出 |
|---|---|---|
| R：证据驱动受控修复 | 原 A：诊断、定位、修复操作；原 D：来源核验、去重、冲突、规模限制 | 当前 skill、轨迹、可用记忆 → 有界候选修改 |
| M：持续失败与修复记忆 | 原 B：独立错题状态；原 C：历次修改与结果 | 有效训练失败和修改事件 → 有界的历史上下文 |

两模块互相配合：M 告诉 R 什么仍没解决、尝试过什么；R 生成可追溯操作；执行结果更新 M。配对门控只控制采用，不抹除问题。

## 4. 研究假设，不是已证明结论

- H1：证据与操作对应能减少泛化空话、重复规则与无关修改。
- H2：独立失败记录使无提升步骤中的持续错误获得后续处理机会。
- H3：保留修改历史能降低反复提出相似无效修复的频率。
- H4：R 与 M 结合的增益可能大于其中任一单独模块；用 2×2 设计检验，不预设必然成立。

已知最近方法覆盖轨迹定位、原子编辑、记忆和搜索。不能宣称“首次用失败修改 skill”或“首次引入记忆”。候选差异是对持续未解决失败的版本化维护、门控独立的记录，以及它与受控修复在有限预算下的作用。相对 AtomSearch/SkillMorph 是否有足够新颖性仍需实验证据。

## 5. CAM 的经验边界

旧 CAM 使用 Qwen target、GLM optimizer，在同一 120 题上的两组种子配对差为 −3.33、+4.17 个百分点，平均约 +0.42，不能证明稳定提升。旧运行还记录七次辅助生成缺失和 prompt 冻结遗漏。

旧机制诊断：8/8 步预算来源未知；记忆在部分类型重现时确有注入，但是否提高质量未得到单组件对照证明。以上是动机与工程经验，不是 ReMem 的结果。来源见 [CAM 复用地图](08_CAM_REUSE.md)。

## 6. 第一轮范围

一个已准备的表格任务环境、一个主执行模型、一个优化器、三个训练种子；不同时加入 RAG、多 agent 协作、全局技能库路由或大规模树搜索。正式运行目标 48–72 小时，环境搭建、算法实施和联调另计。
