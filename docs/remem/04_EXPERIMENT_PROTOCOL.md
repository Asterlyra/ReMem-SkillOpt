# 正式实验协议草案 v0.1

状态：**设计完成、未实现、未冻结、未运行**。本文件提供可审查默认值；准备阶段只允许依据吞吐、数据和实现可行性调整，不能看测试成绩后改协议。

## 1. 研究问题与主比较

主问题：完整 R1M1 是否优于相同基础框架 R0M0，以及 R、M 的作用与交互。外部对照用于区分研究贡献与仅仅改进工程流程。

| arm | R | M | 角色/差异 | seeds |
|---|---:|---:|---|---|
| core_00 | 0 | 0 | 统一门控、无新 R/M 的消融基础 | 42,43,44 |
| repair_only | 1 | 0 | 仅证据驱动受控修复 | 42,43,44 |
| memory_only | 0 | 1 | 仅持续失败与修复记忆 | 42,43,44 |
| remem_full | 1 | 1 | 完整方法 | 42,43,44 |
| skillopt_controlled | — | — | 上游的有界编辑与原生历史机制，统一六步任务预算，关闭 slow/meta | 42,43,44 |
| cam_reference | — | — | 有来源记录的 CAM v3 机制移植，固定旧机制参数，关闭 slow/meta | 42,43,44 |
| atomsearch_budgeted | — | — | 官方代码优先；按总执行预算限制的 AtomSearch，对照其原子编辑/搜索/记忆 | 42,43,44 |

推荐总规模 **7 方法×3 seeds=21 次优化运行**；其中核心 12 次必须作为完整的 2×2 区组执行。初始静态 skill 另做 3 个评估 draw，不训练，不算作 3 次优化。

若准备阶段吞吐预测不能在 72h 内完成，预先选择 **18-run** 版本（去掉 cam_reference 的整个 3-seed 组）。保留近期近邻 AtomSearch；若其实现无法核验，不能悄悄用自由编辑冒充，需在冻结前明确改为“核心机制研究，缺近邻对照”。这两种都不是发表充分性的保证。

## 2. 模型与环境

- 主环境：SpreadsheetBench 已验证的 400 题数据版本；具体来源 revision、题目文件 SHA-256 在 prepare 冻结。
- target：网关别名 qwen；optimizer：glm；只使用 API，不微调模型。
- 网关返回的模型 ID、角色、参数与日期必记；历史名字见模型档案，不把自报身份作为版本证明。
- env.mode=single；目标输出上限起始参考 16,384；目标 worker 起始参考 8、analyst worker 上限 8，共享全局限流。
- 一个实验 lane；不要假设再开多个任务就能线性加速共享网关。
- slow update、meta skill、skill-aware appendix 等额外改写通道在主协议中统一关闭。所有正式修改经过各方法明确路径。

## 3. 数据划分与固定重现

训练池 80、选择集 40、最终测试 120。原数据 split 的 test 池为 280。训练/选择/测试 ID 互斥；若 workbook/source/template 存在共享泄漏，还应按来源分组审计，不能只看 ID 不同。

过去 CAM 已在 120 题上报告结果；其他旧运行可能还使用了其余题。prepare 要汇总所有旧 test manifest/eval IDs 的并集，**只看 ID 和暴露记录，不用旧成绩筛题**。从未暴露且数据齐全的剩余池按任务类型预抽 120，数量不足则公开暴露限制或引入新数据，不能声称“重新随机切分就是全新测试”。

每个 seed 固定同一训练池与选择/测试集，只改变训练顺序和计划重现：

1. step1–4：分层打乱训练池，4×20 覆盖 80 个唯一任务。
2. step5–6：按该 seed 预抽 40 个训练任务，20+20 重现；不是根据某方法的失败情况选题。
3. 所有方法同 seed 共用任务计划；三个 seed 都从相同初始 skill、新的空 M 状态开始。
4. 核心方法执行 120 次训练任务。M 只改变反思可见的历史，不改变执行题目的分布或增加免费重跑。

这样能在有限步数下产生问题重现，观察记忆；但六步仍是短程优化，不能外推长期持续学习能力。

## 4. 门控、候选数和预算公平性

核心四组：每步最多一个实际评估候选、最多 2 条应用编辑，R0 使用固定编辑上限，R1 可以在合法候选不足时少改或不改。反思候选最多 4，不凑数。

共同门控建议：按同一 40 个选择任务逐题配对，bootstrap=10,000、confidence=0.95、meaningful_improvement=0，主消融禁用 soft accept、group guard、drift rollback，减少额外机制。无充分提升证据则保留采用版本，但失败和尝试历史仍保存。统计区间不是反复搜索下的全流程错误率保证。

core_00 不等于原版 SkillOpt：它采用共同门控并关闭跨步历史输入；skillopt_controlled 保留上游自己的编辑/历史/标量门控以作为外部对照。cam_reference 可保留 v3 自身的软接受/分组保护，但必须冻结并明确其整体差异，不能把外部对照当作 R 或 M 的纯因果消融。

目标模型预算：每格最多 **400 次优化阶段 task executions**（不是 HTTP 请求数），另有固定 **120 次最终测试执行**。核心参考分解：120 次训练 + 40 次初始选择 + 最多 6×40 次候选选择 = 400。

缓存只复用同模型版本、skill hash、任务、参数和 draw ID 的既有结果；新 draw 与额外诊断重跑都计入预算。多轮工具调用的一次 task execution 仍可能包含多个 HTTP 请求，分别统计，不能混为同一种成本。

AtomSearch 保留其可核验的搜索机制，优化阶段同样上限 400 次 task executions；并不强制“六步树搜索=六步 SkillOpt”。不足预算时按预先规则停止，最终选择只能用已有选择证据。必须同时报告原论文预算与本预算差异。

优化器所有阶段共享统一调用和输出上限，初始草案每格最多 80 次逻辑调用、每次最多 16,384 输出 tokens；重试另计并受最多 2 次附加尝试限制。正式限值需在准备阶段根据真实阶段需求核对，冻结后不得按方法表现放宽。达到上限的运行记录 budget_exhausted，不假装六步完成。

不得为了匹配实际花费而要求少改的方法生成无意义调用。以相同上限、实际用量和 quality-versus-cost 曲线共同报告；相同上限不等于实际耗费完全相等。

## 5. 三个 seeds 是什么

42/43/44 表示三次独立优化初始化与任务计划编号，不是三个模型，也不是三份互不重叠测试集。相同 seed 方法间配对。模型接口若不支持确定性采样，就记录这一限制；不能仅靠 random.seed 宣称模型输出完全可复现。

同一 120 题重复三次不变成 360 个独立问题。训练 seed 变异与评估任务变异分别报告。

## 6. 隔离与冻结

新 study_id、新输出目录，不覆盖旧记录。freeze 包含完整源码、所有 prompt Markdown、解析后配置、初始 skill、任务 ID 顺序与重现 ID、数据/环境版本、模型返回标识与参数。

训练过程中禁用 test；选定所有 final skill 并保存其哈希后，统一进入最终测试阶段。结果由只读 reporter 聚合；测试成绩不反馈给 optimizer、不决定继续跑哪个 arm。

矩阵按 seed 区组和预先打乱的 arm 顺序运行，避免时间段与方法完全绑定。检查点恢复保留真实事件与缓存身份，不把失败尝试删除后重新算“第一次”。

## 7. 48–72 小时预算

历史四格的训练耗时 4,710–5,860 秒/4步，最终 120 题测试 798–932 秒。六步线性外推约 2.2–2.7 小时/格，来源是旧 CAM 运行，不是新模型 SLA，也不能直接代表 AtomSearch。

| 工作 | 21-run 参考预算 |
|---|---:|
| 优化＋各格最终测试 | 46–57 小时 |
| 3 个静态初始 skill draws | 约 0.7–1 小时 |
| 汇总、固定抽样案例审查 | 2–4 小时 |
| 服务波动与有限重试余量 | 5–10 小时 |
| 总目标 | 约 54–72 小时 |

前 48h 主要完成优化；所有候选冻结后批量最终测试，再完成汇总。实际阶段以校准结果排队，不能用漂亮的整点时间表替代吞吐。准备阶段若 21 格预测超时，切换并冻结 18 格版本；开始后不根据成绩临时砍掉方法或第三个 seed。

服务故障导致无法完成时保留 incomplete/invalid_infra，报告计划未完成。不能保证网关波动下硬性 72h 一定完成。
