# ReMem-SkillOpt 改进点简述

ReMem-SkillOpt 在 SkillOpt 的 skill 文本优化流程上，重点改进“如何修改”和“如何记住失败”。它保留执行模型和优化器模型，只优化 skill 文本。主要设计包括 R、M 两个模块；配对评估门控是共同的质量控制，不作为第三个创新模块。

## 1. R：有证据的受控修复

- **针对具体失败修改**：修复提案关联训练任务、执行轨迹和相关规则，说明诊断、修改操作及预期可观察行为，减少笼统的经验性改写。
- **控制修改范围**：检查证据来源、skill 版本和规则锚点，去重并分离冲突提案，限制每次应用的编辑数量；证据不足时允许不修改。
- **关注已有能力**：提案可引用需要保留的训练成功案例，降低修复一个问题时破坏其他行为的风险。

结构和来源校验只能证明引用及格式一致，不能证明诊断正确或修改有效；仍需要检查轨迹并执行评估。一次组合修改的效果也不能直接归因给其中某一条编辑。

## 2. M：持续失败与修复记忆

- **先记录失败，再尝试修复**：有效训练失败在生成提案之前持久化；没有补丁、格式错误或候选被拒绝时，失败记录仍然保留。
- **分开记录问题与尝试**：失败事件和修复历史分别保存，使后续优化能查看未解决的问题、曾经做过的修改及其结果。
- **状态跟随实际采用的版本**：只有当前采用的 skill 在训练中实际成功，才可将问题标记为观测到解决；候选版本通过但未采用，不会关闭当前版本的错题。
- **限制记忆上下文**：只向优化器提供有限且允许使用的历史，不将验证任务内容、答案或测试反馈混入训练记忆。

目前实现支持同任务的历史检索；跨任务语义检索和冷却调度仍属待实现功能。

## 3. 共同评估与可复现性

候选 skill 使用同一选择集进行配对评估和门控，决定是否采用，避免仅凭提案本身判断效果。R 和 M 可分别开关，以比较各模块的作用；关闭 M 时，离线审计日志不进入模型的历史上下文。

框架还记录失败类别、调用与用量等信息，并冻结源码、配置、任务序列和环境，以便审计及复现。任务失败与基础设施或优化器格式失败分开报告，缺失用量不当作零。

## 当前结论

R/M 核心离线实现及开发版实验框架已建立，也进行了小样本联调。中等诊断受到服务和响应异常影响，尚不能形成完整的方法效果比较；正式实验及最终测试仍未完成。因此，上述内容是方法设计和已有实现的改进点，不是已经证实的性能提升。
